# 사다리 계산

한 번의 주문을 가격 구간에 나눠 거는 규칙입니다. 계산은 `internal/ladder`에 있고 거래소나 데이터베이스에 의존하지 않는 순수 함수입니다.

## 입력

| 항목 | 내용 |
|---|---|
| 시장 | 토스증권 · 업비트 KRW · 업비트 USDT |
| 종목 | 보유 목록에서 선택하거나 직접 입력 |
| 방향 | 매수 · 매도 |
| 기준가 | 현재가 · 평균 매수가 · 직접 입력 |
| 시작 오프셋 | 기준가에서 얼마나 떨어진 곳부터 시작할지 |
| 종료 오프셋 | 어디까지 펼칠지 (시작보다 멀어야 함) |
| 분할 수 | 3 · 5 · 10 · 15 · 20 |
| 총량 | 매도는 수량, 매수는 금액 |

매도는 기준가 위로, 매수는 기준가 아래로 펼칩니다.

## 가격

```
start = 기준가 × (1 ± 시작 오프셋)
end   = 기준가 × (1 ± 종료 오프셋)
p(i)  = start × (end / start)^(i / (n−1))          i = 0 … n−1
```

등비로 배치하는 이유는 가격을 퍼센트로 인식하기 때문입니다. 단계마다 수익률 간격이 일정해지고, 구간이 넓을수록 기준가에 가까운 쪽이 촘촘해져 체결 확률이 높은 구간에 주문이 더 많이 놓입니다.

지수 계산만 부동소수점을 쓰고 결과는 곧바로 호가 단위로 스냅합니다. 금액과 수량 계산에는 부동소수점을 쓰지 않습니다.

**호가 반올림은 유리한 방향으로 고정**합니다.

| 방향 | 반올림 | 이유 |
|---|---|---|
| 매도 | 올림 | 한 틱이라도 비싸게 |
| 매수 | 내림 | 한 틱이라도 싸게 |

반올림한 뒤 같은 가격이 된 단계는 하나로 병합합니다. 미리보기에 `10분할 요청 → 7개 주문 (호가 중복 3건 병합)`처럼 표시합니다.

## 수량

- **매도 — 균등 수량.** 보유 수량을 단계 수로 나누고 시장의 수량 단위로 내림합니다. 토스는 정수 주수, 업비트는 소수점 8자리입니다.
- **매수 — 균등 금액.** 예산을 단계 수로 나누고 각 단계의 가격으로 살 수 있는 수량을 구합니다. 낮은 가격 단계에서 더 많이 사게 되어 평균 단가가 내려갑니다.

나누어떨어지지 않는 나머지는 **기준가에서 먼 단계부터** 한 단위씩 나눠 싣습니다. 매수는 가장 싼 단계, 매도는 가장 비싼 단계가 먼저 받습니다. 체결되면 가장 유리한 쪽이고, 한 단위씩 퍼뜨리므로 특정 단계만 부풀지 않습니다. 한 단계에 몰아주면 20분할 매수의 4분의 1이 가장 비싼 가격에 실리는 일이 생깁니다.

## 수수료

매도와 매수는 거래소가 잠그는 것이 다릅니다.

| 방향 | 잠기는 것 | 수수료 |
|---|---|---|
| 매도 | 주문 수량 그대로 | 체결 후 받는 대금에서 차감 |
| 매수 | 주문금액 × (1 + 수수료율) | 주문을 넣는 순간 함께 잠금 |

그래서 **매수는 예산에서 수수료 몫을 먼저 뺀 뒤** 나눕니다.

```
분할 대상 예산 = 총 예산 ÷ (1 + 수수료율)
```

이 여유가 없으면 주문금액 합계가 예산과 같아지고, 거래소는 거기에 수수료를 더해 잠그려다 실패합니다. 모자라는 양은 `예산 × 수수료율`이라 한 단계보다 작으므로 앞 단계는 모두 들어가고 **마지막 한 단계만** 거절됩니다. 분할 수를 바꿔도 증상이 같습니다.

수수료율은 추정하지 않고 업비트 `/v1/orders/chance`가 알려주는 실제 값을 씁니다. 마켓과 계정에 따라 다르기 때문입니다. 확인하지 못하면 매수를 만들지 않고 멈춥니다. 토스증권은 이 경로로 알려주는 값이 없어 여유를 두지 않습니다.

매수는 어떤 경우에도 잠기는 금액이 예산을 넘지 않습니다. 나눗셈이 항상 내림이기 때문입니다.

## 최소 주문

| 시장 | 최소 |
|---|---|
| 업비트 KRW | 5,000원 |
| 업비트 USDT | 0.5 USDT |
| 토스증권 | 1주 (정수 수량만) |

모든 단계가 이 조건을 통과해야 주문을 만듭니다. 통과하지 못하면 가능한 최대 분할 수를 계산해 그 값으로 바꾸는 버튼을 제시합니다.

## 예시

**매도** — 업비트 KRW-SOL, 기준가 200,000, +2.5% ~ +10%, 10분할, 보유 20

```
  #        가격      수량        금액
  1     205,000         2     410,000
  2     206,700         2     413,400
  3     208,300         2     416,600
  4     209,900         2     419,800
  5     211,600         2     423,200
  6     213,300         2     426,600
  7     214,900         2     429,800
  8     216,600         2     433,200
  9     218,300         2     436,600
 10     220,000         2     440,000

총 수량 20 · 총액 4,249,200 · 평균가 212,460 (+6.23%)
```

**매수** — 업비트 KRW-SOL, 기준가 100,000, −2% ~ −10%, 5분할, 예산 1,000,000, 수수료 0.05%

```
  #        가격          수량        금액
  1      98,000    2.03979642     199,900
  2      95,900    2.08446350     199,900
  3      93,900    2.12886102     199,900
  4      91,900    2.17519097     199,900
  5      90,000    2.22111167     199,900

총 수량 10.64942358 · 총액 999,500 · 평균가 93,854.87
수수료 500 · 잠기는 금액 1,000,000 = 예산
```

주문금액은 999,500이고 거래소가 수수료 500을 더해 1,000,000을 잠급니다. 예산에 정확히 맞습니다. 수수료 몫을 빼지 않았다면 주문금액이 1,000,000, 잠기는 금액이 1,000,500이 되어 마지막 5단계가 거절됩니다.

같은 예산을 수량 균등으로 나누면 평균 단가가 94,000 부근이 됩니다. 금액 균등이 더 낮은 단가를 만듭니다.
