# 포켓 이체

업비트의 개인 메인 포켓과 봇이 거래하는 코트레이더 포켓 사이에서 자산을 옮깁니다. 텔레그램 `/transfer`로 실행합니다.

## 키 세 쌍

| 역할 | 환경변수 접두 | 포켓 종류 | 필요 권한 |
|---|---|---|---|
| 코트레이더 | `UPBIT_COTRADER_` | `user_spot_trading` | 자산조회 · 주문조회 · 주문하기 |
| 메인 | `UPBIT_MAIN_` | `main` | 자산조회 · 주문조회 |
| 관리자 | `UPBIT_POCKET_ADMIN_` | `main` | 포켓관리 |

관리자 키는 이 프로세스에서 거래 외에 자산을 움직일 수 있는 유일한 자격증명입니다. `COTRADER_UPBIT_TRANSFERS_ENABLED=true`일 때만 필요하고, 꺼져 있으면 클라이언트를 아예 만들지 않습니다.

세 키의 access key가 서로 다른지 기동 시 검사합니다. 같은 키를 두 역할에 넣으면 엉뚱한 포켓을 읽거나 쓰게 됩니다.

## 안전 장치

- 어떤 키가 어느 포켓에 속하는지 업비트에 직접 물어 확인합니다. 포켓 종류와 권한이 예상과 다르면 이체하지 않습니다.
- 허용 엔드포인트는 포켓 조회·키 조회·이체 조회·이체 실행 네 가지뿐입니다. 출금 경로는 목록에 없습니다.
- 이체마다 우리가 정한 식별자를 붙입니다. 결과를 읽지 못하면 `확인 필요`로 두고 **식별자로 조회해 정리하며 절대 다시 보내지 않습니다.**
- 결과가 확인되지 않은 이체가 남아 있으면 새 이체를 막습니다.
- 이체 직후 양쪽 잔고를 다시 읽습니다.

## 사용

```
/transfer
 → [메인 → 코트레이더] 또는 [코트레이더 → 메인]
 → 자산 선택 (출발 포켓의 잔고 표시)
 → 금액: 숫자판 입력 또는 [전액 이체]
```

이체는 같은 계정의 포켓 사이에서만 이뤄집니다. 다른 사람에게 보내는 경로는 없습니다.

## 확인되지 않은 이체가 남았을 때

3초마다 식별자로 조회해 완료 또는 실패가 확인되면 정리합니다. 업비트 이력 조회 범위는 7일이므로 그보다 오래된 건은 업비트 앱에서 직접 확인해야 합니다.

이력에 나타나지 않는다고 해서 일어나지 않은 것으로 단정하지 않습니다. 그런 기록은 사람이 확인할 때까지 `확인 필요`로 남습니다.
