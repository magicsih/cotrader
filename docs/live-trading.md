# 실거래 준비와 운영

토스 미국 주식·일반 ETF와 업비트 KRW·USDT 코인을 지정가로 운용한다. 공개 배포 예제는 모든 시장의 실거래가 기본 꺼짐이다. 운영 설정과 실제 전략 시작은 별도이며 설정 변경만으로 새 전략을 만들거나 자금을 배정하지 않는다.

## 시작 절차

1. 시장을 선택하고 `실거래` 화면에서 새 전략 초안을 저장한다. 모의 전략의 `실거래 초안 복사`를 사용할 수도 있다. 원래 모의 전략의 보유분·성과는 옮기지 않는다.
2. `실거래 준비 점검`을 누르고 요청 기록을 확인한다. 사용 가능 현금, 기존 보유분, 수동 미체결, 계좌 수수료와 지원 종목을 확인한다. 업비트는 비체결 주문 테스트를 추가한다.
3. `설정 확인·시작`에서 예산·가격·손실 기준을 확인한다. 엔진이 계좌를 다시 조회하고 시작한다. 준비 점검의 과거 결과만으로 주문을 허용하지 않는다.
4. 토스는 거래 가능 세션, 업비트는 24시간 시세와 신호를 기다린다. 예산은 현금 한도이며 자동 입금·환전하지 않는다.
5. 중단은 웹 또는 Telegram `/pause`를 사용한다. 미체결 취소 결과가 확인될 때까지 엔진과 거래 권한을 유지한다. 보유분은 남으며 시장가 청산하지 않는다.

같은 종목의 계좌 보유 수량이 봇 장부와 다르거나 수동 미체결이 있으면 현금 시작을 거절한다. 기존 보유 코인은 아래의 명시적 전량 편입 절차로 시작한다. 업비트 매수 잔고 부족 `insufficient_funds_bid`는 점검 실패로 표시한다. 필요한 현금은 사용자가 지정한 전략 예산 기준이며 모의 자본과 실제 잔액은 다르다.

업비트에서 다른 코인의 전략이 이미 실행 중이면, 정상 대기 주문을 유지한 채 새 전략의 준비 점검과 시작을 요청할 수 있다. 기존 주문이 실행 중인 실거래 전략의 장부에 속하고, 거래소 미체결 목록과 개별 주문 조회의 식별자·종목·방향·주문 수량·가격·상태·누적 체결 수량·금액·비용이 모두 장부와 일치해야 한다. 확인된 부분 체결도 같은 조건을 적용한다. 점검 도중 새 체결이 발견되면 기존 엔진이 체결을 반영한 뒤 다시 점검한다.

`PREPARED`, `SENDING`, `UNKNOWN`, `PENDING_CANCEL`, 비용 미확정 주문과 같은 코인의 미체결은 계속 시작을 막는다. KRW와 USDT로 나뉜 같은 코인도 중복 배정하지 않는다. 이 점검은 기존 주문을 취소하거나 체결 장부를 수정하지 않으며, 총예산·유의/주의·호가·현재 잔고·시작 승인 검증은 그대로 적용한다.

### 주의 항목별 허용

업비트 전략 카드의 **주의 설정**에서 가격 급등락·거래량 급등·입금량 급등·글로벌 가격 차이·소수 계정 거래 집중을 각각 켜고 끈다. 켠 항목은 해당 주의가 발생해도 이 전략의 거래를 허용한다. 기본값은 모두 차단이며 새 전략 및 보유 전량 초안 준비에서도 같은 항목을 선택할 수 있다. 보유 전량 초안은 선택한 항목을 적용해 거래 상태를 검사한다.

기존 전략의 설정 변경은 승인 대기 또는 중단 상태이고 해당 전략의 미체결·미확인 주문이 없을 때만 가능하다. **주의 설정 저장 → 처리 기록에서 완료 확인 → 설정 확인·시작** 순서로 진행한다. 저장은 보유·현금·주문을 변경하지 않고, 설정 버전을 올려 이전 시작 승인을 무효화하며 변경 전후 항목을 감사 기록에 남긴다. 웹과 Telegram의 시작 확인에 허용 항목을 표시한다.

선택한 항목은 준비·시작 점검, 실행 중 신호 평가, 실제 주문 직전 검사에 동일하게 적용한다. 해당 항목의 주의가 나중에 재발해도 허용 설정을 유지하므로 다시 차단하려면 전략을 중단하고 항목을 끈다. 다른 전략의 설정에는 영향을 주지 않는다. 거래유의 지정, 지원하지 않는 활성 주의, 누락·비정상 상태 응답, 예산·잔고·손실·주문 대조 검사는 계속 차단한다. 자동 전략 탐색은 모든 주의 차단을 유지한다.

[업비트 공식 안내](https://docs.upbit.com/kr/changelog/voc_update)는 별도 지정되는 거래유의와 기준에 따라 자동 지정되는 주의를 구분한다. 주의 허용은 위험이 없다는 판단을 대신하지 않는다.

## 보유 전량으로 시작하는 반복 그리드

업비트 → 포트폴리오 → 실제 계좌의 `전량 반복 그리드 준비`에서 코인을 선택한다. 첫 매도 기준은 평균 매수가와 비용 이상 또는 현재가 한 단계 위 중 고른다. 평균 매수가 기준은 `평균 매수가 × (1 + 수수료 가정) / (1 - 수수료 가정)` 이상이며 현재가 한 단계 위보다 높게 시작한다. 과거 매입 수수료는 현재 비용 가정으로 추정하며 실제 과거 비용을 조회한 값이 아니다. 기본 5단계·2%는 조정 가능한 예시이며 최적화 결과가 아니다.

엔진이 최신 매도 가능 전량·호가·수수료·거래 상태를 조회하고 단계마다 비체결 매도 테스트를 수행한다. 수동 미체결·잠긴 수량·같은 코인의 기존 운용 전략이 있으면 거절한다. `prepare_inventory` 명령은 초안만 저장하며 자산 편입·주문을 실행하지 않는다. `내 전략 → 실거래 → 설정 확인·시작`에서 수량·가격표·손실 한도를 확인한다.

- 시작 시 승인한 전량과 계좌 수량을 다시 대조한다. 평가 기준가에서 0.5% 넘게 변하면 새 초안을 준비해야 한다. 시작한 전략을 재개할 때는 자산을 다시 편입하지 않는다.
- 초기 현금은 0이다. 전량을 단계 수로 균등 분배하고 8자리 소수점 나머지는 마지막 단계에 넣는다. 각 단계는 매도 후 자신의 순매도대금으로만 한 단계 아래에서 재매수한다. 단계별 원래 수량을 초과하지 않으며 이익은 원화로 남긴다.
- 일부 매도 후 가격이 내려오면 매도한 만큼 재매수할 수 있다. 부분 체결·취소·재시작 후에도 단계별 수량과 현금을 유지한다. 다른 단계의 코인·현금과 외부 원화 잔고를 재매수 재원으로 사용하지 않는다.
- 가격 도달 시 종목당 한 주문씩 보낸다. 모든 단계의 지정가를 거래소에 동시에 대기시키는 방식은 아니다. 60초 미체결 취소 확인 후 조건을 다시 평가한다.
- 보유 시작 그리드에는 가격 하단 이탈 중단을 적용하지 않는다. 첫 매도가가 현재가보다 높아도 기다릴 수 있어야 하기 때문이다. 포트폴리오의 하루 손실·고점 대비 손실 한도와 수량 불일치 중단은 계속 적용한다. 중단은 미체결 취소·보유 유지이며 시장가 청산하지 않는다.
- 운용 손익은 초안의 평가 기준가부터 계산한다. 계좌 평균 매수가는 첫 매도 기준과 비교 정보로만 사용하며 기존 손익을 새 전략의 수익으로 기록하지 않는다. 현재 계좌 편입 초안을 과거 백테스트에 넣으면 거절한다.

수량과 자금은 기존 전략 JSON 장부에 저장하며 별도 DB 스키마 변경은 없다. 공개 코드와 테스트에는 개인 잔고·평균 매수가·운영 초안을 포함하지 않는다.

## 서버 설정과 권한

- 토스: `COTRADER_LIVE_ENABLED=true`, `COTRADER_MARKET_SOURCE=toss`, 외부 인증과 기존 계좌 선택.
- 업비트: `COTRADER_UPBIT_ENABLED=true`, `COTRADER_UPBIT_LIVE_ENABLED=true`, 외부 인증. 기존 키에 자산조회·주문조회·주문하기 권한과 클러스터 출발지 IP 허용이 필요하다.
- API와 engine에 같은 비밀이 아닌 운영 설정을 적용한다. 거래소 키는 engine에만 주입한다. research에는 거래소 키가 없다.
- 로컬 `--connect`는 모든 시장의 실거래를 잠근다. 출금·입금·대량 취소·자동 환전 경로는 제공하지 않는다.
- 실거래 플래그를 끄기 전 전략을 중단하고 미체결 취소 완료를 확인한다. 플래그를 끄는 것만으로 거래소의 주문이 사라지지 않는다.

## 체결과 장애 대응

토스는 정수 수량의 `LIMIT + DAY`, 업비트는 8자리 소수 수량의 `limit`와 `smp_type=cancel_taker`를 사용한다. 한 종목에 한 주문을 진행하며 60초가 지난 주문은 취소를 요청한다. 취소 접수와 완료를 구분하고 부분 체결·취소 후 늦은 체결을 장부에 누적한다.

업비트 주문은 내부 주문 ID를 `identifier`로 사용한다. 전송 오류나 모호한 응답이 나면 `UNKNOWN`으로 남기고 식별자로 조회한다. 주문이 없다는 응답을 받아도 새 POST를 보내지 않는다. 동일 시장의 미확인 주문이 있으면 새 주문을 막는다. 재시작 뒤에도 조회·체결 반영을 계속하고 확인할 수 없는 주문은 사용자가 거래소 주문 번호로 대조한다. 업비트는 식별자까지 일치해야 연결한다.

체결 금액은 REST 상세 응답의 실제 거래 금액 합계, 비용은 `paid_fee`를 사용한다. 지정가에 수량을 곱해서 체결 금액으로 추정하지 않는다. 조회 장애가 있으면 신규 주문을 보류하되 이미 중단되었거나 만료된 주문의 취소는 계속 시도한다.

## 검증 범위

자동 테스트는 서명, 시장별 권한 분리, 잔고·수수료·수동 주문, 부분 체결, 중복 반영, 취소, 통신 오류, 식별자 복구를 확인한다. 업비트의 `/v1/orders/test`는 실제 주문을 생성하지 않으며 반환 UUID는 체결·취소 검증에 쓸 수 없다. 테스트 통과는 실제 체결·운영 수익성의 증거가 아니다. 최초 실제 주문은 사용자가 웹에서 전략과 예산을 확인하여 시작한다.
