# 운영

## 주문 켜기

배포와 주문 허용은 별개입니다. 새 이미지를 올린다고 주문이 나가지 않습니다.

```bash
kubectl -n cotrader patch configmap cotrader-config --type merge \
  --patch '{"data":{"COTRADER_UPBIT_KRW_ORDERS_ENABLED":"true"}}'
kubectl -n cotrader rollout restart deployment/cotrader-bot
```

시장별로 따로 켭니다. 토스의 같은 방향 다중 미체결 주문은 아직 실거래로 확인하지 않았으므로(아래 참고) 업비트를 먼저 켜는 편이 안전합니다.

## 주문 상태

| 상태 | 내용 |
|---|---|
| 준비 | 행은 있고 아직 보내지 않음 |
| 전송 중 | 요청 직전에 커밋됨. 프로세스가 죽어도 시도 흔적이 남음 |
| 확인 필요 | 응답을 읽지 못함. **재전송하지 않고** 식별자로 조회하거나 사람이 대조 |
| 대기 | 거래소에서 미체결로 대기 |
| 부분 체결 | 일부 체결된 채 대기 |
| 취소 확인 중 | 취소를 접수했으나 완료 확인 전 |
| 체결 · 취소 · 거절 | 종료 |

`확인 필요`가 하나라도 있으면 그 시장의 새 주문이 전부 막힙니다. 거래소 앱에서 주문을 확인해 실제로 존재하면 그대로 두고, 없으면 `/cancel`로 정리합니다.

## 전송이 중간에 멈췄을 때

한 단계가 실패하면 나머지 단계를 보내지 않고 멈춥니다. 거절 사유는 대개 단계가 아니라 계좌에 있기 때문입니다. 화면에 `나머지 전송`과 `배치 취소`가 함께 나옵니다.

- 사유가 잔고 부족이면 총량을 줄여 새 사다리를 만드는 편이 낫습니다.
- 사유가 `확인 필요`면 먼저 그 주문을 대조해야 합니다.

## 취소

`/cancel`은 진행 중인 모든 사다리의 대기 주문에 취소를 요청합니다. 보유 자산은 매도하지 않습니다.

- 아직 보내지 않은 단계는 그냥 버립니다.
- 대기 중인 단계는 취소를 요청하고 거래소 확인을 기다립니다. **취소 접수는 완료가 아닙니다.**
- 증권사 주문 번호를 모르는 단계는 취소하지 않습니다. 잘못된 주문을 취소할 수 있기 때문입니다.

## 토스 DAY 주문

토스 지정가는 `LIMIT + DAY`라 세션이 끝나면 미체결분이 자동 취소됩니다. 우리가 요청하지 않았는데 사라진 주문은 거래소 취소로 기록하고 사유를 남깁니다. 다음 세션에 이어가려면 같은 설정으로 새 사다리를 만듭니다.

미국 시장이 닫혀 있으면 미리보기가 경고하고 전송 버튼을 숨깁니다.

## 아직 확인하지 않은 것

1. **토스가 같은 종목·같은 방향의 미체결 지정가를 여러 건 허용하는지.** [토스 연동 계약](toss-contract.md)에는 *동일 종목 반대 방향* 미체결 오류만 적혀 있고 같은 방향에 대한 제약 근거는 없습니다. 2주 × 2단계의 작은 주문으로 먼저 확인하세요. 허용되지 않으면 토스는 사다리 방식을 쓸 수 없고 다른 접근이 필요합니다.
2. **토스 보유 응답의 평균 매수가 필드 이름.** 확인되지 않아 값이 없으면 평단 기준 버튼을 숨깁니다. 없는 값을 0으로 만들지 않습니다.
3. **숫자판 12버튼이 리치 메시지에서 읽을 만하게 보이는지.**

## 처음 켤 때

1. 주문을 끈 상태로 배포하고 `/balance`가 양쪽 계좌를 제대로 보여주는지 확인합니다.
2. 업비트 원화 주문만 켜고, 체결되지 않을 먼 가격에 최소 금액 3단계 사다리를 걸었다가 `/cancel`로 회수합니다.
3. 토스를 켜고 2주 × 2단계로 위 1번을 확인합니다.
4. 확인이 끝난 뒤에 실제 운용 금액을 씁니다.

테스트 통과는 실제 체결이나 수익성의 증거가 아닙니다.
