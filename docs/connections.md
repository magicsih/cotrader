# 연결 설정

기본 실행은 모든 시장의 주문이 꺼져 있습니다. 이 상태에서도 잔고 조회, 미리보기, 주문 대조는 동작합니다.

## 환경변수

| 이름 | 내용 |
|---|---|
| `COTRADER_DATABASE_URL` | Go MySQL 드라이버 형식. `사용자:암호@tcp(호스트:포트)/DB` |
| `TELEGRAM_API_KEY` · `TELEGRAM_ME` | 전용 봇 토큰과 본인 사용자 ID |
| `TOSS_INVEST_OPEN_API_CLIENT_ID` · `_SECRET` | 토스증권 OpenAPI |
| `COTRADER_ACCOUNT_SEQ` | 종합매매 계좌가 여러 개일 때 필수 |
| `UPBIT_COTRADER_ACCESS_KEY` · `_SECRET_KEY` | 주문과 잔고 조회에 쓰는 코트레이더 포켓 키 |
| `UPBIT_MAIN_ACCESS_KEY` · `_SECRET_KEY` | 메인 포켓 잔고 조회 |
| `UPBIT_POCKET_ADMIN_ACCESS_KEY` · `_SECRET_KEY` | 포켓 간 이체. 이체를 켤 때만 |
| `COTRADER_TOSS_ORDERS_ENABLED` | 토스 실제 주문 |
| `COTRADER_UPBIT_KRW_ORDERS_ENABLED` | 업비트 원화 실제 주문 |
| `COTRADER_UPBIT_USDT_ORDERS_ENABLED` | 업비트 USDT 실제 주문 |
| `COTRADER_UPBIT_TRANSFERS_ENABLED` | 포켓 간 자산 이동 |
| `COTRADER_UPBIT_ACCOUNT_LABEL` | 화면에 표시할 포켓 이름 |

키 값은 `Secret` 타입으로 감싸므로 어떤 포맷 동사로 찍어도 값이 나오지 않습니다. 켜지 않은 기능의 키는 요구하지 않고, 켠 기능의 키가 빠지면 기동하지 않습니다.

이전 구현은 키 파일 하나의 `UPBIT_OPEN_API_*`가 맥락에 따라 메인 포켓과 코트레이더 포켓을 번갈아 가리켰습니다. 이제 세 역할의 변수 이름이 서로 다릅니다. 로컬 키 파일 `~/.config/upbit/upbit-api-key.env`에서 옮길 때 역할을 다시 확인하세요.

## 텔레그램

- 지정한 사용자 ID와 같은 ID의 **개인 대화방**만 허용합니다. 버튼 응답은 보낸 사람과 대화방을 모두 검사합니다.
- 기존 웹훅이 있으면 기동하지 않습니다. 같은 업데이트를 소비하는 다른 수신자가 우리 버튼에 응답할 수 있기 때문입니다. 웹훅을 자동으로 지우지 않습니다.
- 프로세스 재시작 이전에 그려진 전송 버튼은 거절하고 미리보기를 다시 그립니다. 그 화면은 지금과 다른 잔고와 설정으로 계산되었을 수 있습니다.
- 읽기 전용 이동 버튼은 재시작 후에도 동작합니다.

## 토스증권

토큰은 이 프로세스만 발급합니다. 토스는 새 토큰을 낼 때 이전 토큰을 무효화하므로 발급 주체가 둘이면 서로를 로그아웃시킵니다. 만료 120초 전에 미리 갱신하고, 401 응답은 조회에서만 다시 시도합니다. 주문은 401을 받아도 재전송하지 않습니다.

요청 속도는 응답 헤더가 알려준 한도의 80%로 맞춥니다. 429는 `Retry-After`를 따릅니다.

종합매매 계좌가 하나면 그 계좌를 씁니다. 여러 개면 추측하지 않고 `COTRADER_ACCOUNT_SEQ`를 요구합니다. 계좌번호는 끝 4자리만 표시하고 토큰은 저장하지 않습니다.

## 업비트

비공개 호출은 HS512 JWT로 서명합니다. 서명 대상은 전송 문자열이 아니라 그것을 퍼센트 디코딩한 문자열입니다. 이 규칙은 기존 구현으로 만든 고정 벡터로 검증합니다.

호출 가능한 엔드포인트는 역할별 허용 목록으로 제한합니다. 입출금 경로는 어느 목록에도 없어 어떤 코드 경로로도 도달할 수 없습니다. 요청 간격은 0.2초이고 418·429를 받으면 60초 쉽니다.

`KRW-BTC`, `USDT-SOL` 같은 원화·USDT 거래쌍을 지원합니다. 주문 차단은 시장별로 적용되므로 원화만 열고 USDT는 닫아 둘 수 있습니다.
