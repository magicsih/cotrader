# 그리드 수익 최대 설정 탐색

목표는 **정해진 탐색 범위와 과거 기간에서, 기존 손실 중단 규칙을 적용한 비용 후 총손익을 최대화**하는 것이다. 남은 보유분의 평가손익을 포함한다. 미래 수익의 최대값을 찾았다는 의미가 아니다.

설정을 바꾸어 백테스트를 반복하는 방식은 [Freqtrade Hyperopt의 공식 설명](https://www.freqtrade.io/en/stable/hyperopt/)을 참고했다. 전수 탐색과 Optuna 4.9.0의 무작위·TPE·NSGA-II 탐색을 선택할 수 있다.

## 사용하는 방법

전략 연구실의 **수익 최대 설정 찾기**에 저장된 데이터의 종목과 예산을 입력하고 **수익 최대 설정 탐색**을 누른다. 날짜를 비우면 저장된 구간을 사용한다. 현재 `DEMO`는 가상 예제다.

결과에 탐색 구간 1위, 선정한 설정의 중간 구간 손익, 마지막 구간 손익을 구분해 표시한다. 상위 5개 표에서 선정·제외 이유를 확인할 수 있다. 각각의 설정을 검토용 초안으로 가져올 수 있지만 저장이나 탐색이 거래 시작 승인을 대신하지 않는다.

## 탐색 범위

| 항목 | 후보 |
|---|---|
| 가격 범위 | 탐색 구간 종가 10~90 백분위, 관측 저가~고가, 관측 저가보다 5% 아래~고가보다 5% 위 |
| 매수 단계 | 기본 3, 5, 8, 12 / 확장 3~20의 모든 정수 |
| 가격 간격 | 동일 금액, 동일 비율 |
| 매수 신호 | 필터 없음, EMA 하락 시 신규 매수 보류 |
| 신호 봉 | 필터를 사용할 때 5, 15, 30분 |
| EMA 기간 | 필터를 사용할 때 5/20, 10/40 |

필터 없는 설정 1개와 필터 있는 설정 6개를 사용하므로 기본 `3 × 4 × 2 × 7 = 168`개, 확장 `3 × 18 × 2 × 7 = 756`개다. 같은 설정은 중복 실행하지 않는다. 최소 1주, 호가 단위, 왕복 비용 대비 간격 조건을 만족하지 못하는 조합은 제외하고 개수를 표시한다.

예산, 서버의 하루 손실·고점 대비 하락 한도, 수수료·호가 비용 가정은 검색으로 유리하게 바꾸지 않는다. 비용 입력값은 명시적인 가정이며 실계좌 수수료 확인을 대신하지 않는다. 추세·RSI 독립 전략의 매개변수 탐색은 이 그리드 탐색에 포함하지 않는다.

## 탐색 기법과 비교

| 기법 | 동작 |
|---|---|
| 전수 탐색 | 유효한 조합 전체를 실행. 작은 기본 범위에서는 확실한 비교 기준 |
| 무작위 | 같은 범위에서 무작위 표본 추출. 다른 기법의 성능 비교 기준 |
| TPE | 앞선 결과의 확률 분포를 참고하는 베이지안 최적화 |
| NSGA-II | 세대별 후보 선택, 교차·변이를 사용하는 유전 알고리즘 |
| 3가지 비교 | 무작위·TPE·NSGA-II를 같은 시드와 기법별 시도 횟수로 실행하고 탐색 구간의 결과 비교 |

[Optuna 공식 sampler 비교](https://optuna.readthedocs.io/en/stable/reference/samplers/index.html), [NSGA-II](https://optuna.readthedocs.io/en/stable/reference/samplers/generated/optuna.samplers.NSGAIISampler.html), [TPE](https://optuna.readthedocs.io/en/stable/reference/samplers/generated/optuna.samplers.TPESampler.html)를 기준으로 구현했다. 직접 만든 유전 알고리즘을 사용하지 않는다.

확률적 기법의 기본값은 100회·시드 42이며 기법당 20~1,000회까지 지정할 수 있다. 같은 유효한 첫 후보에서 출발한다. NSGA-II는 세대당 10개, TPE는 초기 10회 탐색 후 관측 결과를 사용한다. 모든 기법은 직렬 실행하며 전수 탐색에는 시도 횟수와 난수 시드가 적용되지 않는다.

확률적 기법은 수익 최대화와 최대 하락폭 최소화를 두 목표로 탐색한다. 최종 후보 선정 점수는 `총손익 - 하락폭 가중치 × 최대 하락폭`이다. 기본 가중치 0은 수익 최대, 웹에서는 1 또는 2도 선택할 수 있다. API는 0~5를 허용한다. 가중치는 **후보 순위 기준**이며 실제 손실 한도는 바꾸지 않는다.

시도 횟수에는 유효하지 않은 설정과 중복 표본도 포함한다. 유효하지 않은 표본에는 지배당하는 벌점 결과를 반환한다. 같은 설정은 다시 백테스트하지 않고 계산 결과를 재사용한다. 따라서 기법별 시도 수, 고유 설정 수, 제외·중복 수를 구분한다. 비교 모드에서도 각 기법은 자체 관측 이력만 사용한다.

비교 모드에서는 세 기법이 찾은 모든 후보를 합친 후 상위 5개를 중간 기간에서 비교한다. **기법마다 마지막 기간을 시험해 승자를 고르는 방식은 사용하지 않는다.** 탐색 결과가 기대보다 나쁘더라도 최종 기간을 본 뒤 다시 탐색하거나 다른 후보를 자동 시험하지 않는다.

## 기간 분리와 선정

1. 시간순 **앞 60%**에서 가격 범위를 산출하고 선택한 기법으로 유효 조합을 탐색한다. 선정 점수 순으로 정렬하고 동률이면 최대 하락폭이 작은 설정을 우선한다.
2. 상위 5개만 **중간 20%**에서 다시 실행한다. 앞·중간 구간이 모두 비용 후 이익, 완료된 매수·매도 묶음 3회 이상, 중단 기준 미도달을 만족하면 선정 대상이다. 그중 중간 구간 선정 점수가 가장 높은 하나를 선정한다.
3. 선정 결과를 고정한 뒤 **마지막 20%**를 단 한 설정에만 실행한다. 마지막 구간 결과를 보고 다른 후보로 교체하거나 순위를 다시 매기지 않는다.
4. 중간 구간을 통과한 후보가 없으면 앞 구간 1위를 최종 확인 대상으로 표시하되 추천은 보류한다. 마지막 구간도 같은 성과·거래 수 조건을 만족해야 추천 후보가 된다.

각 구간은 같은 초기 예산과 빈 보유 상태에서 독립 실행한다. 이전 구간의 과거 봉은 신호 계산 준비에만 사용한다. 이전 구간의 현금·보유량·고점은 넘기지 않으며, 세 구간 수익을 합쳐 연속 운용 수익이라고 표시하지 않는다.

실제 데이터가 20일분 미만이거나 가상 데이터가 포함되어 있으면 추천을 보류한다. 20일은 UTC 날짜별 관측 유무를 센 초기 선별 기준이고, 통계적 신뢰나 충분한 시장 국면 검증을 보장하지 않는다. 완료 매수·매도 3회 기준 역시 초기 필터다.

## 재현성과 중단

결과에 전체 데이터 확인값, 구간별 실제 시각·봉 수, 설정 ID, Optuna 버전, 기법·시드·시도 수·진행 이력, 비용·손실 한도, 선정 이유를 저장한다. 과거 6개 조합 비교 기록은 계산 당시 결과 그대로 보존한다. 새 탐색 결과는 `optimizer_version: 2`로 구별한다.

연구 작업은 주문 실행기와 별도 프로세스에서 한 번에 하나씩 실행한다. 작업 중 진행률을 기록하며 대기·실행 작업을 웹뷰에서 중단할 수 있다. 계산 중단은 거래 전략 중단과 별개다. 백테스트의 봉 집계는 미리 계산하되 각 시점에 이미 닫힌 봉만 노출한다.

많은 설정을 같은 데이터로 반복 선택하면 과거에만 맞춘 결과가 나올 수 있다. 특히 결과를 본 뒤 기간·비용·조건을 바꾸어 반복하면 마지막 구간도 선정에 간접 사용한 셈이 된다. 실제 운용 판단에는 새 기간의 검증과 모의 운영이 필요하다. 기업행사·환율·세금·실제 주문 대기열 미반영 등 기본 백테스트의 한계도 그대로 적용된다.


## 결과 비교와 기간별 재검증

연구실의 **최적화 결과 비교**에서 완료된 탐색 최대 5개를 선택한다. 데이터 확인값, 종목, 예산, 수수료·호가 비용, 손실 한도가 동일한지 표시한다. 조건이 다른 결과에는 비교 주의를 표시하며 자동으로 승자를 고르지 않는다.

**기간별 재검증**은 원래 탐색의 종료 시각 이후에 있는 서로 겹치지 않는 2~6개 기간을 받는다. 원래 상위 후보 중 최대 5개를 선택할 수 있고, 서버가 저장한 설정과 비용·손실 한도를 그대로 복사한다. 새로운 가격 범위나 매개변수를 탐색하지 않는다. 기간당 최소 300봉, 전체 최대 100,000봉이며 미래 기간은 거부한다.

각 기간은 같은 예산과 빈 보유 상태에서 시작하고 해당 기간보다 앞선 데이터만 신호 준비에 쓴다. 결과에는 기간별 비용 후 손익·수익률·최대 하락·완료 매수와 매도 횟수·중단 여부·데이터 확인값을 남긴다. 평균 수익률은 기간별 단순 평균이며 연속 운용이나 복리 수익률이 아니다. 이미 접수한 작업의 손실 한도는 실행 시 서버 설정이 바뀌어도 유지된다.

기존 추천 기준을 통과한 원래 선정 설정이 새 기간에서도 모두 최소 성과 기준을 충족하고 실제 관측 날짜가 20일 이상일 때만 추가 모의 운영 검토 후보로 표시한다. 다른 비교 후보와 가상 데이터, 부족한 검증은 연구용으로 남긴다. 비교 후 다른 설정을 채택하려면 새로운 기간에서 다시 확인해야 한다. 이 기능은 매 구간에서 재학습하는 자동 walk-forward 최적화와 구별되는 **고정 설정의 기간별 검증**이다.

시간순 분리와 테스트 구간 반복 사용의 한계는 [scikit-learn의 공식 검증 안내](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-of-time-series-data)를 따른다. 같은 기간을 반복 요청한 결과를 독립 검증 횟수로 합산하지 않는다.

## 추천 설정 보관함

완료된 탐색·재검증 결과의 후보를 이름과 함께 저장한다. 추천 보류 상태도 **연구용**으로 보관할 수 있다. 서버가 원본 결과에서 설정, 판정 이유, 데이터 확인값, 비용·손실 기준과 근거 확인값을 저장하며 클라이언트가 보낸 대체 설정이나 판정을 사용하지 않는다. 같은 결과·후보를 다시 저장해도 중복 생성하지 않는다.

**모의 전략 초안 만들기**는 항상 `paper` 모드의 승인 대기 전략만 생성한다. 같은 저장 항목에서 초안을 반복 생성하지 않으며 자금 배정·주문·시작 명령을 만들지 않는다. 전략 화면에서 현재 운영 손실 한도와 설정을 확인하고 별도로 시작해야 한다. 보관함은 MySQL의 `recommendations` 테이블에 저장되므로 프로세스를 재시작해도 유지된다.
