# 보유 장부를 기존 초안에 인계하기

전략 중단은 보유 자산과 배정 예산을 유지한다. 보유가 남은 전략을 중단한 뒤 같은 종목 초안을 만들면, 중복 배정 검사 때문에 새 초안은 시작되지 않는다.

실거래 초안의 **기존 전략 보유 인계**에서 원본·대상 이름과 수량을 확인한다. 기존 전략은 중단 상태여야 하며 미체결·미확인 주문이 남아 있으면 인계를 거절한다.

인계는 한 DB 트랜잭션에서 다음을 처리한다.

- 두 전략의 설정 버전과 확인값, 실제 잔고, 시장 경보, 수수료, 주문 가능 여부, 운용 한도를 다시 검사한다.
- 대상 초안의 가격표를 유지하고 보유 평가 기준가·예산만 최신 호가로 갱신한다. 초안의 승인 버전을 올려 과거 시작 요청이 재사용되지 않도록 한다.
- 원본을 종료하고 보유 장부의 관리 주체를 대상 초안으로 넘긴다. 실제 매도·환전·자산 이전은 없다.
- 원본의 현금·실현 손익·수수료·체결 기록을 보존한다. 인계 전 전체 보유 장부도 이벤트에 보존한다. 평가액은 현금이나 매도 수익으로 기록하지 않는다.
- 대상은 미배정 DRAFT로 유지한다. 실제 계좌의 코인은 그대로이며 새 전략 시작 시 편입한다.

같은 시장에서는 원본 예산을 해제한 결과와 기존 손익을 반영해 한도를 계산한다. 원본·대상 예산을 동시에 합산하거나 계좌 운용 한도를 자동으로 올리지 않는다.

인계 후 **실거래 준비 점검 → 설정 확인·시작**은 별도다. 평가 기준가에서 0.5% 넘게 움직이거나 잔고·경보 조건이 바뀌면 시작 단계에서 다시 거절할 수 있다.

명령은 기존 `prepare_inventory`에 `source_strategy_id`, `source_version`, `source_approval`과 `target_strategy_id`, `target_version`, `target_approval`을 전달한다. 대상 ID를 지정하면 저장된 가격표가 우선하며, 신규 그리드 생성용 가격 기준·단계·간격으로 덮어쓰지 않는다. 대상은 같은 종목·시장의 미배정 실거래 초안이어야 하며 주문 기록이 없어야 한다. 같은 시장에서 새 초안을 만드는 원본 지정도 지원한다.

실제 주문을 생성하지 않는 검증에는 [업비트 주문 생성 테스트 API](https://docs.upbit.com/kr/reference/order-test)를 사용한다. 실행 중인 엔진 외부에서 유지보수 작업을 수행할 때는 엔진을 정지하고 동일한 `cotrader:engine` 단일 실행권을 확보한 뒤 같은 애플리케이션 서비스를 호출해야 한다. 임의 SQL로 보유량을 0으로 만들거나 `funded` 검사만 해제하지 않는다.
