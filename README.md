# Cotrader

토스증권 미국 주식·일반 ETF와 업비트 원화 코인을 위한 개인용 전략 검증·운용 앱입니다. 그리드, 추세 추종, 과매도 반등 전략을 텔레그램과 웹에서 관리합니다. USD와 KRW 예산·원장·위험 기준은 각각 계산합니다. 두 시장 모두 계좌 조회·공개 시세·백테스트·최적화·모의매매와 지정가 실거래를 지원합니다. 실거래는 시장별 서버 허용과 전략별 시작 확인이 필요하며 입출금 기능은 없습니다.

기본 설정은 외부 연결과 실거래가 꺼져 있습니다. 계좌와 거래 내역은 운영자의 MySQL에 저장하며 공개 저장소에 포함하지 않습니다. 웹 로그인은 GitHub·Telegram을 지원합니다.

웹의 **사용 가이드**에서 실제 종목 수집 → 설정 탐색 → 기간별 재검증 → 모의매매를 따라 할 수 있습니다. `/guide`는 로그인 없이 열리는 설명 페이지이며 계좌 정보는 포함하지 않습니다.

[인증 설정](docs/github-auth.md) · [공개·비공개 구분](docs/privacy.md) · [업비트 연결](docs/connections.md#업비트)

## 기본 운영 설정

| 항목 | 설정 |
|---|---|
| 사용자·계좌 | 본인 한 명, 토스증권·업비트 계좌 조회 |
| 상품 | 미국 보통주·레버리지 없는 ETF, 업비트 원화 코인; 공매도·신용·파생·자동 환전 제외 |
| 거래 시간 | 주식은 토스 캘린더의 세션, 코인은 24시간 |
| 모의 예산 | 주식 USD 5,000, 코인 KRW 1,000,000; 각각의 전략 예산 합계가 총예산 이하 |
| 모의 중단 기준 | 주식 하루 USD 50·고점 대비 USD 250, 코인 하루 KRW 10,000·고점 대비 KRW 50,000 |
| 기준 도달 | 봇 대기 주문 취소, 보유 유지, 알림; 자동 재개 없음 |
| 그리드 | 앱이 가격선을 감시하고 종목별 주문을 직렬 제출 |
| 실행 권한 | 설정·예산·위험 기준 확인 후 전략 승인; 매 주문 승인 불필요 |

하루 손실과 고점 대비 하락은 평가손실과 비용을 포함합니다. 중단 기준은 손실을 그 금액으로 보장하는 장치가 아닙니다. 중단 후 보유분의 평가손익은 계속 변합니다.

## 로컬 실행

Python 3.13 이상, Node 24, pnpm, Docker가 필요합니다. 검증은 Python 3.14와 MySQL 9.2를 기준으로 합니다.

```bash
uv sync --frozen
pnpm --dir web install --frozen-lockfile
pnpm --dir web build
bash scripts/local-db.sh start
uv run alembic upgrade head
```

각각의 터미널에서 실행합니다.

```bash
uv run cotrader engine
uv run cotrader research
uv run cotrader api
```

[로컬 웹뷰](http://127.0.0.1:8000)를 엽니다. 로컬 인증은 loopback에서만 허용되며 외부 주소 바인딩을 거절합니다. 개발 DB는 별도 Docker 컨테이너와 볼륨을 사용하고 운영 MySQL에 접속하지 않습니다.

```bash
bash scripts/local-db.sh stop
```

중단해도 개발 DB 볼륨은 유지합니다. `.env.example`은 설정 목록입니다. 기본 실행은 실제 키 파일을 읽지 않습니다. Telegram과 실제 계좌 조회를 연결하려면 api와 engine에 `--connect`를 추가합니다. 이 옵션은 역할별 기존 키 파일을 읽고 주문을 비활성화합니다. [연결 방법과 조회 범위](docs/connections.md)를 참고하세요.

## 사용 흐름

1. **새 전략**에서 종목, 예산, 전략을 입력합니다. 그리드는 상·하단, 단계 수, 동일 금액·비율 간격을 선택합니다. 저장은 주문을 실행하지 않습니다.
2. 시장을 선택하고 **전략 연구실 → 시장 데이터**에서 토스 또는 업비트 시세 수집을 요청하거나 사용 권한이 있는 CSV·JSON을 가져옵니다. 미국 주식은 `AAPL`, 업비트는 `KRW-BTC`처럼 입력합니다. 시세 연결 전에도 가져온 데이터의 백테스트가 가능합니다.
3. **그리드 설정 찾기**에 종목과 예산을 입력합니다. 전수·무작위·TPE·유전 알고리즘 NSGA-II 또는 세 기법 비교를 선택합니다. 기본 168개·확장 756개 범위에서 수익 또는 수익과 하락폭을 함께 평가합니다. 앞 60%의 선정 점수 상위 5개를 중간 20%에서 비교하고, 선정한 1개를 마지막 20%에서 확인합니다. 추천 보류 사유와 기간별 성과를 확인한 뒤 검토용 초안으로 가져옵니다. [탐색 범위와 판정 기준](docs/optimization.md)을 참고하세요.
4. **설정 확인·시작**에서 실행 모드, 예산, 가격 범위, 위험 기준을 확인합니다. 설정 버전과 위험 기준의 확인값이 바뀌면 이전 승인은 거절됩니다.
5. 텔레그램 `/account`로 토스, `/crypto`로 업비트 계좌를 조회합니다. `/guide`, `/status`, `/strategies`, `/pause`, `/web`으로 운영합니다. `/pause`는 두 시장의 주문을 중단하고 보유 자산을 유지합니다.

CSV는 따옴표나 쉼표가 포함되지 않은 숫자 데이터 형식입니다.

```csv
timestamp,open,high,low,close,volume
2026-09-01T13:30:00Z,100,101,99,100.5,10000
2026-09-01T13:31:00Z,100.5,102,100,101,12000
2026-09-01T13:32:00Z,101,101.5,100,100.2,11000
```

이는 **형식 예제**이며 실제 종목의 시장 데이터가 아닙니다. JSON은 `timestamp, openPrice, highPrice, lowPrice, closePrice, volume` 필드의 배열을 사용합니다. 한 번에 20,000봉까지 가져오며 기존 시세를 덮어쓰지 않습니다.

## 전략과 주문 규칙

- **그리드:** 가격선마다 같은 통화 예산을 나눕니다. 주식 수량은 정수, 코인은 소수점 8자리까지 내림합니다. 최소 1주 또는 5,000원과 왕복 비용 조건을 만족하지 못하면 설정을 거절합니다. 처음 켰을 때 즉시 매수하지 않으며 봇이 산 수량만 다음 가격선에서 매도합니다. 한 번에 여러 선을 넘으면 현재 가격에 가까운 한 단계만 매수합니다.
- **신호 조건부 그리드:** 단기 평균이 장기 평균 아래에서 하락 중이면 신규 매수를 보류합니다. 보유분의 그리드 매도는 계속 허용합니다.
- **추세 추종:** 완성된 봉의 단기·장기 EMA 상향 교차에 매수하고 하향 교차에 매도합니다. 기본 기간은 20·60입니다.
- **과매도 반등:** RSI가 30을 위로 회복하고 가격이 장기 EMA 위일 때 매수합니다. RSI 55 도달 또는 장기 EMA 이탈에 매도합니다. 기본 RSI 기간은 14입니다.

전략 수치는 검증용 시작값입니다. 동일 종목에는 한 전략만 예산을 배정하며 최대 5종목을 운영합니다. 그리드 가격 범위를 자동으로 확대하거나 예산을 자동 증액하지 않습니다. 전략 설정은 저장 후 불변이며 변경할 때 새 초안을 만듭니다. 자금과 보유분을 유지하는 중단 전략은 예산 배정을 계속 차지합니다. 보유 수량과 대기 주문이 모두 0이면 **운영 종료·예산 해제**로 기록과 누적 손익을 보존하면서 배정을 해제합니다.

토스 실제 주문은 정수 수량의 `LIMIT + DAY`입니다. 한 종목에 한 주문만 진행하며 60초 동안 남은 주문은 취소 후 상태를 확인합니다. 호가 차이와 시세 신선도를 확인하고, 미체결·부분 체결·취소 중·응답 미확인을 구분합니다. 실제 수수료가 승인된 비용 가정을 넘으면 실거래 신규 주문을 보류합니다. 업비트 실거래는 원화 지정가와 주문 식별자를 사용합니다. 불명확한 주문은 식별자로 조회하며 재전송하지 않습니다. [실거래 준비와 운영 절차](docs/live-trading.md)를 참고하세요.

## 백테스트를 읽는 방법

총손익, 보유분 평가손익, 비용, 최대 하락폭, 단순 보유 비교, 거래 수, 사용 데이터 확인값을 제공합니다. 종료 보유분을 지운 채 실현이익만 보여주지 않습니다.

1분봉에서는 봉 안의 가격 순서를 알 수 없습니다. 이전 봉에서 만든 주문만 다음 봉에서 체결할 수 있고, 가격선에 닿기만 한 경우는 미체결로 봅니다. 한 봉 거래량의 1%까지 체결을 가정하며 같은 봉 안에서 연쇄 매수·매도를 만들지 않습니다. 실시간 모의매매는 현재 호가와 잔량의 10%를 사용하므로 백테스트와 결과가 달라질 수 있습니다.

토스 수정 전 가격과 업비트 체결 기반 봉을 사용합니다. **분할·배당·환율·양도소득세와 과거 호가 대기열은 미반영**입니다. 업비트 과거 호가 단위 변경도 재현하지 않고 현재 규칙을 적용합니다. 기업행사가 있는 구간은 실거래 검증 근거로 쓰지 않아야 합니다. 데이터 공백을 채워 넣지 않고 개수와 실제 사용 범위를 표시합니다. 연결되지 않은 시세·미확정 비용을 확정된 0으로 취급하지 않습니다.

## 검증

```bash
uv run ruff check src tests migrations
uv run pytest -q
bash scripts/test-mysql.sh -q
pnpm --dir web build
uv run alembic check
kubectl kustomize deploy/k8s
```

MySQL 테스트는 무작위 로컬 포트의 임시 컨테이너를 사용하고 끝나면 폐기합니다. 테스트 DB 이름과 호스트를 검사하므로 운영 DB에 테스트용 테이블 삭제를 실행할 수 없습니다.

구조와 실패 대응은 [설계 문서](docs/architecture.md), Kubernetes 준비 항목은 [배포 절차](docs/deployment.md), API 제약과 확인 근거는 [토스 연동 기록](docs/toss-contract.md)을 참고하세요.

검증 방법과 시뮬레이션 한계는 [검증 문서](docs/verification.md)에 정리했습니다.
